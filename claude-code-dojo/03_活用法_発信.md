# 三 活用法・発信

## 発信の型

Threadsは、リサーチ → 型を見つける → 投稿を作る → 伸びたものをテンプレにする、の繰り返しです。この1周を、Claude Codeで回します。

1. リサーチする
2. 型を見つける
3. 投稿を作る
4. 伸びたらテンプレに

### 4 リサーチする

同じジャンルで伸びている投稿を、スクショかコピーで research フォルダに入れて渡します。1行目・型・数字・伸びた理由を表にまとめます。

プロンプト（research/ に投稿を入れてから送る）

```
research/ に入れた投稿（スクショでもコピーでもOK）を全部読んで、伸びている投稿を表にして。

列は、1行目・型・表示やいいねの数・伸びた理由。

research/伸びた投稿.md に保存して。本文はまるごと写さないで
```

実際に送った結果：練習用に、同じジャンルの投稿14本（1行目と数字）を research/ に入れて送った。できた research/伸びた投稿.md の要旨：

- 元データ: research/投稿データ.txt（2026/11/10〜11/21、14件。1行目と数字のみ）
- 基準: 表示が8,800以上の7件を「伸びた」とした。表示4,100と8,800の間に大きな谷があり、ここで自然に2グループに分かれる
- 型と理由は1行目だけから読み取ったもの。本文は元データに含まれていない

| 1行目 | 型 | 表示 / いいね | 伸びた理由 |
|---|---|---|---|
| 会議メモをAIに渡すとき、この一文を足すだけで変わります | 一文テンプレ | 21,600 / 512 | 会議メモという会社員なら毎日ある場面を名指し。「一文を足すだけ」で手間ゼロの結論を先に出している |
| AIに仕事を丸投げする人が、最初にやっている3つのこと | 数字付きリスト | 18,400 / 402 | 「丸投げ」が読む人の理想を言い当てている。3つと数を切って、中身を見たくさせる |
| AIで副業を始める前に、3つだけ知っておいてほしいこと | 数字付きリスト | 15,200 / 330 | 「始める前に」で初心者を主語にしている。3つだけ、で読む負担を小さく見せている |
| AIを1年使ってわかった、やめた方がいい頼み方5選 | 数字付きリスト | 12,800 / 261 | 1年という実績の数字と5選のリスト数字が両方入っている。「やめた方がいい」で損失回避を突く |
| AIに「調べて」とだけ頼むのは、もうやめてください | 失敗パターン指摘 | 11,900 / 244 | 「調べて」と頼む具体的な場面を出し、大半の読者が自分のことだと分かる。命令形で言い切っている |
| その頼み方、AIが一番困るやつです | 失敗パターン指摘 | 9,600 / 188 | 「その頼み方」と読者に向けて断定し、何が困るのか知りたくさせる。短くて話し言葉 |
| 無料でここまでできるのに、使わないのはもったいない | もったいない訴求 | 8,800 / 150 | 無料という条件と「もったいない」の損失感。ただし具体的なツール名も数字もなく、7件の中では最下位 |

伸びなかった7件との違い：伸びなかった7件（表示1,800〜4,100）は、雑談、朝の挨拶、質問の投げかけ、ニュースまとめ、設定の注意喚起。どれも1行目に、読む人の得になる数字や、次にやることにつながる場面がない。

例外が2件ある。「朝5分で終わる、Museの使い方を紹介します」は、5分という数字とツール名があるのに4,100止まり。「紹介します」と前置きで終わり、結論が1行目に出ていないのが原因。「ChatGPTの設定、初期のままだと会話が学習に使われます」はツール名も場面も結論もそろっているのに3,200。内容の条件は満たしているので、朝7:40の投稿時間が足を引っ張った可能性を疑う材料になる。

投稿時間も分かれていた。伸びた7件は全部19〜22時台、伸びなかった7件は全部7〜13時台。ただし内容の差と完全に重なっているので、時間だけの効果かは分からない。次に試すなら、同じ型の投稿を朝と夜で出して比べる。

次に書くときの型：

1. 場面を名指しして、手間の小さい結論を1行目に出す（会議メモ型）
2. 「3つ」「5選」で数を切る（リスト型）
3. 読者のよくある頼み方を取り上げて、言い切りで指摘する（失敗指摘型）

### 5 型を見つける

リサーチの表から、自分のジャンルでも使える型だけを抜き出して、型のファイルにします。文章はまねずに、型だけ借ります。

プロンプト（リサーチのあとに送る）

```
research/伸びた投稿.md から、私のジャンルでも使える型を5つ抜き出して。

型ごとに、名前・1行目の作り方・本文の流れ・字数をまとめて、templates/型.md に保存して。

文章はまねないで、型だけにして
```

実際に送った結果（templates/型.md の内容）：

- 元ネタ: research/伸びた投稿.md（表示8,800以上の7件）
- ジャンル: AIの仕事での使い方。読む人はAIを仕事で使い始めた30代の会社員
- 注意: 元データは1行目と数字だけで、本文は含まれていない。だから「1行目の作り方」は伸びた投稿から取った型、「本文の流れ」と「字数」はCLAUDE.mdの投稿ルール（100〜300字、言い切り、数字・ツール名・場面を入れる）から組んだもの。文章はまねていない。穴埋めの枠だけにしてある

#### 型1: 場面名指し＋手間ゼロ結論型

伸びた理由: 会社員なら毎日ある場面を名指しして、「これだけやればいい」という手間の小さい結論を1行目で出し切っている。前置きがない。元ネタの中で表示が一番多かった型。

1行目の作り方：[毎日ある仕事の場面]＋[手間の小さい動作（一文足す、一語変える、1回押す）]＋[変わる・終わる・済む]

- 場面は読む人が今週やったものにする。議事録、日報、メール返信、資料の要約、Slackの返事
- 動作は30秒以内で終わるものにする。手間が大きいと「あとで読む」になる
- 1行目で結論を言い切る。「紹介します」「解説します」で終わらない

本文の流れ：

1. 1行目: 場面と結論
2. 何を足す・変えるのかをそのまま書く（枠の中身を1つだけ）
3. 足す前と足した後で何が変わるかを1〜2行。数字が入れば入れる
4. 使うツール名を1つ添えて終わる。補足は足さない

字数：120〜200字。結論が小さいので本文も短くする。200字を超えたら説明を削る

#### 型2: できる人の行動リスト型

伸びた理由: 「仕事をAIに任せ切っている人」という読む人の理想像を出し、その人がやっている行動を3つなどの数で切っている。数が見えると中身を見たくなる。

1行目の作り方：[読む人がなりたい人物像]＋[その人に共通する行動を指す言葉（共通点・習慣・手順・ルール）]＋[3つ]

- 人物像は読む人の半歩先にする。「AIに資料作りを任せている人」「AIで残業を減らした人」「AIの返事をそのまま使える人」
- 数は3にする。5以上は行動リストだと長く感じる
- 人物像を先に置いて、読む人が自分と比べたくなる形にする。「〜な人の共通点3つ」「〜できる人の手順は3つだけ」「〜な人のルール3つ」のどれでもいい

本文の流れ：

1. 1行目: 人物像と数
2. 行動1〜3を1行ずつ。各行に具体的な動作とツール名か数字を入れる
3. 最後に、読む人が今日ひとつ試せる行動を1つ指す
4. まとめの一文は書かない。3つ出したら終わる

字数：180〜280字。1項目50字前後×3、残りは1行目と締め

#### 型3: 損失回避リスト型

伸びた理由: 「やめた方がいい」「始める前に知っておいて」と、損をしない方向で数を切っている。初心者を主語にし、「3つだけ」「5選」で読む負担を小さく見せている。実績の数字（使った期間など）を添えると信じやすくなる。

1行目の作り方：

- パターンA: [実績の数字（使った期間・回数・件数）]＋[その結果を示す動詞（気づいた・やめた・変えた・捨てた）]＋[損を示す言葉（損する・遠回り・時間が溶ける）]＋[対象]＋[数]
- パターンB: [初心者の時期を示す言葉（使い始めの1週間・最初の1か月・導入前）]＋[数＋だけ]＋[先に押さえてほしいこと・先に決めること・先にやらないこと]

- 対象は読む人の手の中にあるものにする。頼み方、設定、使う場面、ツールの選び方
- 実績の数字は本当のものだけ使う。期間、回数、件数
- 「だけ」「〜選」「〜個」で数を切る。「いろいろ」「たくさん」は使わない
- 損を示す言葉は毎回変える。同じ言い回しが続くと型が読者に見える

本文の流れ：

1. 1行目: 損失の方向と数
2. 項目を1行ずつ。各行は「やりがちなこと」→「なぜ損か」を短く
3. 1項目だけ、代わりにどうするかを足す。全部に足すと長くなる
4. 言い切って終わる。「かもしれない」は使わない

字数：200〜300字。5項目なら300字近くまで、3項目なら200〜250字

#### 型4: 失敗パターン指摘型

伸びた理由: 読む人がよくやる頼み方や使い方を具体的に取り上げて、「それ、やめてください」「それが一番困るやつです」と言い切っている。大半の読者が自分のことだと分かる。短くて話し言葉。

1行目の作り方：

- パターンA: [読む人が実際に打っている短い頼み方]＋[それが起こす結果の言い切り（返事がぼやける・3往復増える・やり直しになる）]
- パターンB: [読む人の行動を指す言葉（その・毎回の・いつもの）]＋[頼み方・使い方・設定]＋[AI側の困り方か読む人の損を一言で]

- 頼み方は読む人が本当に打っている言葉にする。「いい感じにして」「直して」「まとめて」「わかりやすく」
- 結果か損で言い切る。命令で止めるだけでなく、何が起きるかまで1行目に入れると「やめてください」系と差がつく
- 疑問形にしない。断定で終わる
- 20字前後まで短くする。この型は長いと効かない

本文の流れ：

1. 1行目: 失敗パターンの名指し
2. なぜ困るのかを1〜2行。AIが何を補えないか、何を勝手に決めてしまうか
3. 代わりの頼み方を1つ、そのまま打てる形で書く
4. 変わった結果を1行で示して終わる

字数：100〜180字。1行目が強いので本文は短く。180字を超えたら「代わりの頼み方」以外を削る

#### 型5: 無料・コストゼロ訴求型（改良版）

伸びた理由: 「無料でここまでできる」という条件と「使わないのはもったいない」という損失感。ただし元ネタではツール名も数字もなく、7件の中で表示が最下位だった。この型を使うときは、ツール名と数字を必ず1行目に足す。

1行目の作り方：[ツール名]＋[無料・0円・標準機能・契約なし]＋[できることを数字で]＋[使っていない人への損の言い切り（払い過ぎ・手作業のまま・時間を捨てている）]

- ツール名は必ず入れる。ChatGPT、Gemini、Copilot、NotebookLMなど実際に使ったもの
- 数字は「月〇円分」「〇分かかる作業が〇分」「〇機能」のどれかを入れる
- 損の言い切りは「もったいない」以外の言葉から選ぶ。元ネタの弱い部分をそのまま引き継がない
- 何ができるかを1行目で見せる。損の感情だけで引っ張らない

本文の流れ：

1. 1行目: ツール名、無料の条件、数字
2. 無料でできることを2〜3個、1行ずつ。各行に仕事の場面を添える
3. 有料との差を1行。「無料で足りる」か「ここから有料」かを言い切る
4. 今日試す1手を1つ書いて終わる

字数：150〜250字。ツール名と数字が入る分、型1より少し長い

#### 5つの使い分け

| 型 | 向いている中身 | 1行目の長さ | 字数 |
|---|---|---|---|
| 1 場面名指し＋手間ゼロ結論 | 小さなコツ1つ | 25〜35字 | 120〜200 |
| 2 できる人の行動リスト | 習慣・やり方3つ | 25〜35字 | 180〜280 |
| 3 損失回避リスト | 失敗・注意点3〜5つ | 25〜35字 | 200〜300 |
| 4 失敗パターン指摘 | 頼み方の直し方1つ | 15〜25字 | 100〜180 |
| 5 無料・コストゼロ訴求 | ツール紹介 | 25〜40字 | 150〜250 |

### 6 投稿を作る

ネタを決めて、型のファイルの型に流し込みます。書き方は基本の型の CLAUDE.md で決まっているので、ここではネタだけ書きます。

プロンプト（〇〇にネタを入れて送る）

```
ネタは〇〇。templates/型.md の型を使って、Threadsの投稿を10本作って。

型は5つ全部使って、10本とも違う場面にして。

threads/posts.csv に保存して（列：番号, 型, 投稿文）
```

実際に送った結果（型のファイルを読んで、10本できた）：

1. 型1：文字起こしを議事録にするとき、この一文を足すだけで直しが消えます。足すのは「決まったことと、誰がいつまでに何をやるかを分けて書いて」。これがないと、発言の要約がだらだら並ぶだけの議事録が返ってきます。足した後は、決定事項3行とToDoの表に分かれて出てくるので、直すのは名前の漢字くらい。ツールはChatGPTで十分です。
2. 型1：日程調整メールの返事、AIに一文足すだけで往復が1回で済みます。足すのは「相手が選ぶだけで済む形で」。「候補を出して」だけだと、空いている時間をずらずら並べた文になる。この一文で、候補3つが箇条書きになり、最後に「ご都合の良い番号を返信ください」が付く。2往復が1往復になりました。Geminiで試しています。
3. 型2：AIに企画書の構成を任せている人の共通点は3つです。1. 白紙から頼まない。社内で通った企画書を1本貼って「この構成で」と言う。2. 先に決めるのは枚数。「10枚で」と切ると、1枚に1メッセージの構成が返ってくる。3. 最初に出た構成を信じない。「読む人が最初に反論する点はどこ」と1回聞いて穴を埋める。今日やるなら2番。次に作る資料の枚数を先に決めて、そこから頼んでみてください。
4. 型2：AIの書いたメールをそのまま送れる人の手順は3つだけ。1. 相手のメールを全文貼る。3行に要約して渡すと、相手が本当に聞きたい点が落ちる。2. 結論を自分で1行書く。「受けます、ただし納期は来週」まで決めてから「これをメールに」と頼む。3. 相手との関係を一言添える。「取引3年目の担当者」と書くと、敬語の硬さがちょうどになる。まず2番から。次に返すメール1通、結論を1行決めてから頼んでみてください。
5. 型3：会議録音のAI文字起こし、最初の1か月で先に決めることは3つだけ。1. 録音すると参加者に言う。黙って回して後で知られると、次から本音が出なくなる。これが一番の遠回り。2. 固有名詞の一覧を先に渡す。人名、商品名、社内用語。これがないと、佐藤さんが砂糖になった文を毎回直す羽目になる。3. 全文を議事録にしない。60分の会議は文字起こしで1万字を超える。議事録は決定事項とToDoだけに絞る。代わりは2番だけ書いておきます。Googleドキュメントに名前の一覧を1ページ作って、毎回それを冒頭に貼る。直しが半分以下になります。
6. 型3：資料のチェックをAIに任せる前に、3つだけ先に押さえてください。1. 「おかしいところを直して」で丸ごと渡さない。数字まで勝手に丸められて、元の資料より悪くなる。2. 誤字と論理の確認を同時に頼まない。両方頼むと、誤字は拾うが論理の穴はほぼ見落とす。3. 社外秘の数字をそのまま貼らない。無料版は、入力が学習に使われる設定が初期値のツールがある。代わりの頼み方は1番。「直さずに、おかしいと思う箇所を行番号で指摘して」と頼むと、直すかどうかを自分で選べる。時間が溶けるのは、直された資料を元に戻す作業です。
7. 型4：「催促メール書いて」で、角が立つ文が返ってきます。AIは相手との関係も、何回目の催促かも知らない。だから無難に強い文を書く。代わりにこう打つ。「先週金曜が期限の見積書、1回目の催促。相手は普段やりとりの多い取引先。急かさず、今週中にもらえるか聞く文で」。これで、そのまま送れる文が1回で出ます。
8. 型4：「会議の内容まとめて」だと、自分の宿題が埋もれます。AIは誰が読むかを知らない。だから全員向けに均等な要約を返して、欠席者が本当に知りたい2点が後ろに沈む。欠席した人に送るなら、こう頼む。「読む人は欠席した田中さん。田中さんに振られた宿題と、田中さんの案件で変わったことの2点だけ。他は1行で」。返ってくるのは5行。読む側も5秒で終わります。
9. 型5：NotebookLMは無料でPDF50本が読める。手でめくる時間、捨てています。無料でできること3つ。・過去の提案書を全部入れて「去年の案件で単価はいくらだった」と聞く。・100ページの業界レポートを入れて、会議前に「結論と根拠の数字だけ」で3分で把握。・答えに引用元のページが付くので、上司に「どこに書いてある」と聞かれても即答。社内資料を読む用途なら無料で足りる。今日やるなら、机の上のPDF3本を入れて、1つ質問してみてください。
10. 型5：ChatGPTは無料で英文メール返信が書ける。辞書を引く30分、手作業のままです。無料版でできること。・相手の英文を貼って「日本語で3行に要約」。読む時間が10分から1分。・日本語で返事の要点を書いて「丁寧なビジネス英語に」。書くのは日本語3行だけ。・返ってきた英文を「この文で失礼な箇所はある」と聞き返す。送る前の不安が消える。英文メールだけなら無料で足りる。有料が要るのは、1日に何十往復もする人だけ。今日来た英文メール1通、要約から試してみてください。

### 7 伸びたものをテンプレにする

投稿して数字が出たら、伸びた投稿をネタを入れ替えれば何度でも使えるテンプレにします。次の週は、ここから始めます。

プロンプト（data/ に今週の数字を置いてから送る）

```
data/今週の数字.csv を見て、伸びた投稿トップ3を出して。

その3本を、ネタを入れ替えれば何度でも使えるテンプレにして、templates/伸びたテンプレ.md に足して。

伸びなかった型は、templates/型.md に「様子見」と書いて
```

実際に送った結果（templates/伸びたテンプレ.md）：

- 元データ: data/今週の数字.csv と threads/posts.csv（2026/11/24時点、10件）
- 基準: 表示のトップ3。いいね順でも同じ順位になった
- 型の説明は templates/型.md にある。ここは、実際に伸びた文をそのまま骨にして、ネタの部分だけ［ ］で空けたもの。［ ］を埋めれば投稿文になる
- 書くときの約束は CLAUDE.md のとおり。言い切る、数字とツール名を入れる、ダブルクォートと太字の記号は使わない

#### 1位: 番号3（型2 できる人の行動リスト）
